## Findings

- major · git history (`0e9ae76`, `076131f`) · The 23 per-item TDD cycles were squashed into one commit, and the contract helper was committed together with its tests, so test-first is unverifiable. This breaks instructions.md:404-416 and ground rule 9. · For future work, commit each red→green cycle as `backend <n>: <behaviour>`. For this build, record the deviation honestly.
- major · BUILD_REPORT.md:23 · "Deviations: None" is inaccurate. The required per-item commits and the `backend 24: conformance suite` commit are missing. · List these commit-granularity deviations under "Deviations from instructions".
- minor · conformance/assets.test.ts:60 · The conditional assertion (`if 201 … else 409`) accepts either outcome, so the ISBN-10 `x` normalisation is not reliably checked over HTTP. · Generate a unique valid ISBN-10 per run (as `isbn13()` already does for ISBN-13) and assert 201 and `080442957X`-style normalisation unconditionally.
- minor · frontend/src/App.test.tsx:178 · The mock response bypasses `contractJson` and uses a non-contract message (`'x'`). This violates "every mock response goes through it" (§3.3). · Use `contractJson('GET', '/assets', 500, { error: { code: 'INTERNAL_ERROR', message: 'Internal server error' } })`.
- minor · frontend/src/api/client.test.ts:46 · The mock `HttpResponse.json({})` skips the contract helper. · Route it through `contractJson` against a contract operation, or reuse `/api/assets`.
- minor · backend/test/http/create-asset.test.ts:27-31,101,112-120 · Some HTTP responses (201 without ISBN, 415 charset, 400 could-not-be-read, empty-body 400) are never validated with `assertMatchesContract`, though §2.3 says every HTTP test does. · Add `assertMatchesContract(...)` to each response.

## Summary

The service is functionally solid. Every automated gate, the acceptance oracle, the conformance suite and the audit pass. The code is clean, secure and closely follows the contract and §4 decisions. The weak points are process and reporting: the commit history shows no TDD cadence (all 23 backend items in one commit), and the build report says there were no deviations. A few tests also skip the contract helper. Fix the report and tighten those tests before shipping.
